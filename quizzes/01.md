### Answer Key

1. **B — The Host is the end-user application (e.g., Claude Desktop) holding model context, while the Client is the protocol layer establishing connections to an MCP server.**
   * *Explanation:* The Host manages LLM interaction, context assembly, and user permissions. The Client is the protocol endpoint communicating with the Server.

2. **C — Read-only Resource with a URI like `git:///repo/commits`**
   * *Explanation:* Resources provide safe, read-only data access with zero side effects. Tools should be reserved for operations that execute actions or mutations.

3. **B — It allows an MCP server to request LLM reasoning from the host without requiring the server to hold its own sensitive Anthropic API keys.**
   * *Explanation:* Sampling centralizes API keys, user consent, and token usage inside the Host, preventing third-party servers from requiring raw API keys.

4. **C — Standard Input/Output (`stdio`)**
   * *Explanation:* Local tools run as sub-processes where communication occurs directly over stdin/stdout pipes, minimizing networking overhead and attack surface.

5. **B — Declaring top-level filesystem boundaries and URI roots to restrict where a server is authorized to read or write files.**
   * *Explanation:* Roots inform the server about workspace boundaries, helping enforce sandbox restrictions and preventing path traversal attacks.

6. **B — `/.well-known/agent.json`**
   * *Explanation:* In the A2A standard, agents publish their discovery metadata (`AgentCard`) at `/.well-known/agent.json`.

7. **B — As stateful Tasks that transition through explicit states (`submitted`, `working`, `input-required`, `completed`, `failed`).**
   * *Explanation:* Tasks provide durable state tracking across network reconnections and support human-in-the-loop workflows via the `input-required` state.

8. **C — Artifact**
   * *Explanation:* Artifacts represent durable output deliverables associated with a Task and support chunked streaming updates.

9. **A — MCP is designed for vertical client-to-server connectivity (connecting an agent downward to tools/resources), while A2A is designed for horizontal peer-to-peer collaboration (connecting autonomous agents to other agents).**
   * *Explanation:* MCP connects a reasoning model to local/remote tools and data sources. A2A allows distinct agents with separate models/identities to delegate tasks and collaborate.

10. **B — Confused Deputy; mitigated by strict privilege scoping, user-consent elicitation, and validating authorization context.**
    * *Explanation:* When an agent acts on behalf of an unverified caller without checking authorization boundaries, it acts as a confused deputy. Mitigation requires explicit consent, scoped permissions, and parameter validation.
